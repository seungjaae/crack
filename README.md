# Concrete to Code — Bridge Crack Extraction Engine

교량 프리캐스트 바닥판을 드론으로 촬영한 **정사영상(GeoTIFF)** 에서,
현장 작업자가 균열 위에 칠해 둔 **락카 색상선을 자동 추출**하여
**CAD 데이터(DXF) 와 좌표표(TSV)** 로 변환합니다.

소프트웨어가 균열 자체를 찾는 것이 아니라 **'색상'을 인식**합니다.
현장에서는 폭을 재서 정해진 색으로 덧칠만 하면 됩니다.

```
정사영상(GeoTIFF)  →  색상 분리  →  노이즈 제거  →  세선화 · 분기 분할  →  DXF / TSV
```

## 균열 폭 등급

| 등급 | 기준 | 기본 색상 | DXF 레이어 |
|:--:|---|:--:|---|
| **W1** | 0.1mm 이상 ~ 0.2mm 이하 | Red | `CRACK_W1_0.1-0.2` |
| **W2** | 0.2mm 초과 ~ 0.3mm 이하 | Yellow | `CRACK_W2_0.2-0.3` |
| **W3** | 0.3mm 초과 | Cyan | `CRACK_W3_0.3-` |

0.1mm 미만은 균열로 보지 않으므로 현장에서 칠하지 않습니다.
**색상과 등급의 짝은 `config/default.toml` 에서 바꿀 수 있습니다.** 현장 색상 규칙이
바뀌어도 코드는 건드릴 필요가 없습니다.

## 설치

```bash
py -3 -m venv .venv
.venv\Scripts\python -m pip install -e .
```

## 사용법

```bash
crack ortho.tif -o out
```

| 옵션 | 설명 |
|---|---|
| `-c, --config` | 설정 TOML 경로 (기본 `config/default.toml`) |
| `-o, --out-dir` | 출력 폴더 (기본 `out`) |
| `--tile-size` | 타일 한 변 픽셀 수 (기본 4096) |
| `--gsd` | mm/픽셀. 좌표계 없는 영상(JPG 등)에 사용 |
| `--sort` | 정렬 기준 `grade_length`(기본) / `grade` / `length` / `length_desc` / `id` |
| `--preview-by-color` | 색상(등급)별 미리보기를 한 장씩 따로 저장 |
| `--girders` | 거더도 함께 검출해 DXF 레이어와 TSV 로 출력 |
| `--no-dxf` / `--no-tsv` / `--no-stats` / `--no-preview` | 개별 출력 생략 |

### GUI (임계값 튜닝)

```bash
crack-gui
```

현장 조도와 락카 상태에 따라 색상 임계값은 반드시 조정이 필요합니다.
GUI 는 축소본 위에서 슬라이더를 움직이며 **검출 결과를 즉시** 보여 주고,
확정된 값으로 원본 해상도 추출을 돌린 뒤 그대로 내보냅니다.

- 색상별 탭에서 **H 시작/끝, 최소 채도(S), 최소 명도(V)** 조정
- 보기 전환: `원본` / `색상 마스크` / `추출 결과`
- **표시할 색상** 체크박스로 등급별로 켜고 끄며 확인
- **선 편집** — 잘못 추출된 선을 클릭해 선택하고 삭제. 되돌리기 / 전체 복원 지원
  (단축키 `Delete`, `Ctrl+Z`). 삭제한 선은 통계와 내보내기에서 함께 빠집니다
- **선 추가** — 색상을 고르고 캔버스를 클릭해 놓친 균열을 직접 그려 넣습니다
  (더블클릭 또는 `Enter` 로 완료, `Backspace` 마지막 점 취소, `Esc` 그리기 취소)
- 조정한 임계값은 **설정 파일에 저장** 버튼으로 `config/default.toml` 에 반영
- 추출은 별도 스레드에서 돌아 UI 가 멈추지 않습니다

### 출력물

| 파일 | 내용 |
|---|---|
| `*.dxf` | 등급별 레이어 분리, `LWPOLYLINE` + 길이 `TEXT` 병기. AutoCAD 2010 이상 |
| `*.tsv` | `id, grade, color, source, length_mm, paint_width_mm, start/end 좌표, WKT` (탭 구분) |
| `*_stats.tsv` | 속성값 분석표. 폭별 · 길이별 · 총합 (엑셀에서 바로 열림) |
| `*_preview.png` | 검수용. 원본 위에 추출된 선을 겹쳐 그림 |
| `*_preview_W1_red.png` 등 | `--preview-by-color` 로 **색상별 한 장씩** 따로 저장 |

좌표는 GeoTIFF 에 들어 있는 **실제 측량 좌표계를 그대로 사용**합니다 (예: EPSG:5186).
별도 정위치 작업이 필요 없습니다.

## 검수와 수정

추출 결과를 그대로 믿고 내보내는 것이 아니라, 확인하고 고칠 수 있게 해 둡니다.

- **색상별로 나눠 보기** — 세 색을 한 장에 겹쳐 보면 서로 가려 검수가 어렵습니다.
  GUI 의 `표시할 색상` 체크박스, CLI 의 `--preview-by-color` 로 색상별로 떼어 봅니다.
  다른 색은 원본 그대로 남아 있어 위치 대조가 됩니다.
- **잘못 추출된 선 삭제** — GUI 에서 선을 클릭하면 흰색으로 강조되고 길이·등급이
  표시됩니다. `Delete` 로 지우고 `Ctrl+Z` 로 되돌립니다. 지운 선은 자리를 알 수 있게
  회색으로 흐리게 남습니다. **삭제 결과는 통계와 DXF/TSV 내보내기에 그대로 반영**됩니다.
- **놓친 선 직접 추가** — 현장 마커는 붓칠이라 농도와 굵기가 고르지 않습니다.
  흐리거나 끊긴 구간은 자동 추출이 놓치므로, 색상을 고르고 캔버스를 클릭해
  직접 그려 넣습니다. 점을 찍는 동안 길이가 실시간으로 표시됩니다.
  직접 그린 선도 자동 추출된 선과 똑같이 선택 · 삭제 · 집계 · 내보내기됩니다.
- **자동인지 수동인지 구분** — TSV 의 `source` 열이 `auto` / `manual` 을 기록합니다.
  검수 때 어느 선이 사람 손을 탔는지 알 수 있어야 하기 때문입니다.

## 거더 검출

균열과 달리 거더는 색으로 구분할 수 없습니다. 거더와 바닥판이 같은 콘크리트라
경계에 색 차이가 없기 때문입니다. 대신 거더는 **기하가 매우 규칙적**입니다 —
전부 평행하고, 폭이 같고, 등간격으로 놓입니다. 이 규칙성을 근거로 찾습니다.

```bash
crack ortho.tif -o out --girders        # CLI
```

GUI 에서는 툴바의 **거더 검출** 버튼. 균열 추출 전이라도 거더만 따로 돌릴 수 있습니다.

1. 긴 직선들의 길이가중 원형평균으로 거더 방향을 **소수점까지** 구합니다.
   정수로 반올림하면 1,700px 거더의 끝단이 10px 밀립니다.
2. 그 방향이 세로가 되도록 회전합니다.
3. 열별 **중앙값 밝기**로 거더 띠를 찾습니다. 합계는 거더가 세로로 얼마나 길게
   찍혔는지에 휘둘리지만, 중앙값은 그 열이 거더 위인지를 바로 답합니다.
4. 폭이 정상인 띠들에 **등간격 격자**를 맞춥니다. 격자는 가려진 거더의 위치도 알려줍니다.
5. 길이는 확신도 높은 거더들의 **합의값**을 씁니다. 한 경간의 거더는 끝단이 거의
   정렬돼 있고, 자체 측정이 합의값보다 크게 짧으면 가려진 것입니다.

현장 사진에서 수작업으로 표기한 거더 6개와 대조한 결과 **6개 모두 검출, IoU 평균 0.872**.

| 출력 | 내용 |
|---|---|
| DXF `GIRDER` 레이어 | 초록 폴리라인 + `G1 769x26mm` 텍스트 (`GIRDER_TEXT`) |
| `*_girders.tsv` | 폭 · 길이 · 네 꼭짓점 좌표 · WKT POLYGON |

**한계** — 절반 넘게 가려진 거더는 중앙값 원리상 찾을 수 없습니다.
설정은 `[girder]` 블록 (없어도 기본값으로 동작).

## 속성값 분석

추출이 끝나면 자동으로 집계합니다. CLI 는 콘솔에 표를 찍고 `*_stats.tsv` 를 남기며,
GUI 는 우측 패널에 같은 표를 띄웁니다.

- **폭별 분류** — 색상이 곧 폭 등급이므로 W1/W2/W3 별 개수 · 연장 · 비율
- **길이별 분류** — 구간별 개수 · 연장, 그리고 **구간 x 등급 교차표**
- **총연장 합계** — 전체 및 등급별. 평균 · 중앙값 · 최소 · 최대 포함
- **정렬** — 색상순, 길이순 등. DXF/TSV 의 행 순서도 이 기준을 따릅니다

길이 구간의 경계는 `config/default.toml` 의 `[analysis] length_bins_mm` 에서 바꿉니다.
GUI 에서는 값을 고치면 **재추출 없이** 분석만 즉시 다시 계산됩니다.

```
─ 폭별 분류 (색상 = 균열 폭 등급) ────────────────────────
  등급  색상      기준 폭                 개수   연장(m)  연장비율
  W1    red       0.1mm이상 0.2mm이하       23     17.01    39.3%
  W2    yellow    0.2mm초과 0.3mm이하       22     13.65    31.5%
  W3    cyan      0.3mm초과                 15     12.68    29.3%
  합계                                      60     43.34   100.0%

─ 길이별 분류 ────────────────────────────────────────────
  구간                 개수   연장(m)   비율    W1   W2   W3
  300 mm 미만            20     4.29   33.3%     7    8    5
  300 ~ 600 mm           10     4.57   16.7%     4    4    2
  600 ~ 1,000 mm         13     9.79   21.7%     5    6    2
  1,000 ~ 2,000 mm       16    22.24   26.7%     6    4    6
  2,000 mm 이상           1     2.45    1.7%     1    0    0
```

## 설계상의 요점

- **길이(`length_mm`)** 는 직선거리가 아니라 **균열을 따라간 실연장**입니다.
- **가지친 균열은 분기점에서 쪼개어** 세그먼트마다 길이를 따로 냅니다.
  Y자 균열은 3개의 행으로 나옵니다.
- **노이즈 제거** 는 세 단계입니다 — 채도 기반 색상 분리(무채색 콘크리트 탈락),
  모폴로지 + 최소면적, 그리고 세그먼트 단위의 **길이 · 세장비(길이/폭)** 필터.
  낙엽이나 흙 얼룩처럼 뭉툭한 것은 세장비에서 걸립니다.
- **타일 처리** — 원본 RGB 를 통째로 메모리에 올리지 않고 타일 단위로 읽습니다.
  GSD 0.5mm 에서는 영상이 쉽게 수억 화소가 되기 때문입니다.
- 딥러닝을 쓰지 않습니다. 락카는 고채도, 콘크리트는 무채색이라 HSV 공간에서
  잘 갈리고, 임계값이 **사람이 읽고 조정할 수 있는 값**으로 남습니다.

## 검증

실제 드론 데이터가 오기 전까지는 합성 정사영상으로 검증합니다.
콘크리트 질감 위에 그림자 · 타이어 자국 · 흙 얼룩 · 낙엽을 깔고,
정답 좌표를 아는 3색 균열(Y자 분기 포함)을 그립니다.

```bash
.venv\Scripts\python tools/make_synthetic.py     # 합성 영상 + 정답 생성
.venv\Scripts\python -m crack.cli tests/fixtures/synthetic_deck.tif -o out
.venv\Scripts\python tools/verify.py             # 정답과 대조
.venv\Scripts\python -m pytest tests/ -q
```

최근 결과 — **6/6 검출, 평균 절대오차 0.62%, 최대 1.54%, 오검출 0건**

| 정답 | 색상 | 정답(mm) | 측정(mm) | 오차 |
|:--:|:--:|--:|--:|--:|
| 1 | red | 650.0 | 648.6 | −0.22% |
| 2 | red | 777.8 | 777.1 | −0.09% |
| 3 | yellow | 1041.6 | 1041.5 | −0.01% |
| 4 | cyan | 360.6 | 366.1 | +1.54% |
| 5 | cyan | 357.9 | 352.9 | −1.41% |
| 6 | cyan | 461.0 | 458.8 | −0.47% |

## 구조

```
config/default.toml     색상 정의 · 등급 매핑 · 임계값
src/crack/
  config.py             설정 로딩과 검증
  raster.py             GeoTIFF I/O, 픽셀 <-> 실좌표, 타일 분할
  segment.py            HSV 색상 분리, 모폴로지, 최소면적 필터
  skeleton.py           세선화 -> 그래프 -> 분기 분할 -> RDP 폴리라인
  model.py              CrackSegment
  stats.py              속성값 분석 (폭별·길이별 분류, 총연장, 정렬)
  export.py             DXF / TSV / 통계 TSV / 미리보기 PNG
  pipeline.py           전체 흐름 조립
  cli.py                명령줄 진입점
  gui.py                임계값 튜닝 GUI (PySide6)
  girder.py             거더 검출 (방향 → 회전 → 중앙값 프로파일 → 격자)
tools/
  make_synthetic.py     검증용 합성 정사영상 생성
  verify.py             정답 대조
```
